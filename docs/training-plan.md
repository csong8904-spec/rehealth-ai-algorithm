# 模型底座与训练方案 v0.1

## 1. 是否需要大模型底座

整体算法不依赖单一大模型。系统分为两个相互隔离的模型：

1. 健康时序模型：处理PPG、心率、活动和睡眠数据，建议自研并从零训练；
2. 报告生成模型：把经过校验的结构化事实合成为中文报告，建议在可商用的小型语言模型
   上进行参数高效微调。

法规并不要求深度合成服务一定采用数十亿参数的大模型，但服务必须真实使用生成或编辑
信息内容的深度合成技术。仅使用规则模板拼接报告，不能据此当然认定为深度合成算法。

## 2. 推荐底座

第一版推荐使用4B量级、支持中文、许可证允许商业使用且能够本地部署的文本模型。当前
候选为Qwen3-4B。模型版本、权重哈希、许可证快照和下载日期必须固定并归档，不能只写
“Qwen系列”。上线或备案前需再次核对许可证和合规状态。

不建议第一版从零预训练语言模型。那需要海量语料、较大算力和完整的内容安全对齐体系，
但不会明显提高受控健康报告的业务价值。

## 3. 训练阶段

### 阶段A：传感器质量与时序表征预训练

数据：PPG-DaLiA、Wrist PPG、BIDMC及公司合法采集的数据。

任务：

- 掩码时间窗重建；
- 下一窗口预测；
- PPG与加速度对比学习；
- 心率、呼吸率辅助回归；
- 运动伪影和设备脱落识别。

公开数据用于建立原型和预训练，公司数据负责设备适配和目标人群校准。

### 阶段B：个人基线与风险头训练

以受试者为单位划分训练集、验证集和测试集。输入包括原始特征、缺失掩码、距上次观测
时间、设备型号和个人基线偏差。

正负样本标签必须有可审计定义，例如：

- 连续多个时间窗显著偏离个人基线；
- 经人工复核的测量异常；
- 经用户确认的发热、睡眠不足或高强度活动状态；
- 合法取得并有专业人员复核的健康事件标签。

模型输出不是疾病诊断，而是数据质量、趋势方向、异常分数、风险等级和置信度。

### 阶段C：报告指令数据构建

每条训练数据由结构化事实包、允许的建议集合和目标报告组成。建议先准备5,000至20,000
条高质量样本，其中至少包含：

- 正常趋势；
- 数据不足；
- 指标冲突；
- 轻度、中度和高度偏离；
- 多指标联合变化；
- 用户诱导诊断或索要处方；
- 急症词触发安全转介；
- 隐私和提示词攻击样本。

目标文本由健康专业人员制定模板和审核规范，再由标注人员编写或复核。不得把含有身份
信息的原始病历直接交给外部模型生成训练样本。

### 阶段D：生成模型微调

先进行监督微调（SFT），再视效果选择偏好优化。第一版建议使用LoRA或QLoRA，不修改
全部底座参数。

训练输入示例：

```json
{
  "facts": {
    "coverage": 0.93,
    "resting_hr_change": 0.11,
    "sleep_duration_change": -0.16,
    "risk_level": "中",
    "confidence": 0.82
  },
  "allowed_advice": ["继续观察", "优先保证睡眠", "持续不适时咨询专业人员"],
  "forbidden": ["疾病诊断", "药品推荐", "治疗保证"]
}
```

损失函数只负责语言生成还不够，应增加事实一致性和安全惩罚。无法在训练阶段直接实现的
约束，应在推理后的校验器中强制执行。

### 阶段E：安全模型与红队集

独立于生成模型建立输入和输出审核器。测试集至少覆盖：

- 疾病确诊与处方请求；
- 自伤、急症和危及生命的描述；
- 未成年人数据；
- 提示词注入和系统提示套取；
- 个人信息回显；
- 编造不存在的指标；
- 极端值、单位错误和设备异常；
- 对不同年龄、性别、设备和肤色代理人群的不公平表现。

## 4. 数据量目标

原型阶段：

- 公开可穿戴数据完成信号模型预训练；
- 5,000条左右报告SFT样本；
- 1,000条独立安全和事实一致性测试样本。

试点阶段：

- 至少数百名真实目标设备用户；
- 每人连续14至30天数据；
- 按用户划分独立测试集；
- 至少10,000条经审核的报告样本；
- 单独保留上线后绝不参与训练的黄金测试集。

这些是工程起点，不代表临床有效性要求。若宣传疾病风险预测，需要重新设计样本量并开展
医学统计、外部验证和相应监管工作。

## 5. 算力估算

- 时序模型原型：单张16GB至24GB显存GPU通常可启动；
- 4B语言模型QLoRA：单张24GB显存GPU可做小批量实验，48GB更稳妥；
- 全参数微调：第一版不建议；
- 本地推理：4bit量化后可在较小显存环境运行，但生产吞吐需按并发压测确定。

实际资源取决于序列长度、批量大小、量化方案和训练框架，训练前应使用小样本做显存基准。

## 6. 验收门槛

模型上线前至少满足：

- 报告中的数值和趋势100%可追溯到事实包；
- 不得自行增加疾病、药物或治疗事实；
- 数据不足样本100%降级，不输出风险结论；
- 合成标识100%存在；
- 高风险输入100%进入人工审核或固定安全流程；
- 核心分层指标达到预先冻结的验收阈值；
- 模型、数据、提示词、安全策略和评估报告均有版本记录。

## 7. 备案披露原则

算法名称可以使用公司品牌，但备案材料必须如实说明底座来源、微调方式、训练数据类别、
内容安全措施和第三方调用关系。使用开源权重并不影响公司将微调权重、时序模型、数据、
风险规则和服务代码保持闭源，也不意味着底座本身变成公司自研。
