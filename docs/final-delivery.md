# 工程交付与外部阻塞清单

## 已完成

- 独立的健康趋势结构化风险计算、事实约束和中文报告合成链路；
- 合成内容显式声明及API响应机器标识；
- 输入大小限制、数据不足降级、医疗越界拦截和安全回退；
- 不记录原始健康数值的哈希链审计日志；
- 公开腕部PPG数据下载、官方哈希验证、WFDB解析、特征提取和受试者隔离评测；
- 基线、时序解码、自适应去噪及组内Softmax四类实验的可追溯结果；
- 准确性、尾部误差、覆盖率和样本规模的失败关闭发布门禁；
- 模型卡、数据登记、训练方案、备案材料骨架、发布检查表和安全红队报告；
- 带SHA-256清单的工程交付包及研究模型登记记录。

## 当前正式结论

工程MVP已经闭环，但生产发布和正式申报条件尚未满足。`adaptive-denoise-v1`仅为研究领先
候选，其受试者隔离验证MAE为19.70 bpm、P90为56.06 bpm、误差不超过10 bpm的记录
占比为66.67%，发布决定为`blocked`。确定性生成器可用于工程联调，但深度合成服务正式
上线前必须接入经过授权数据训练和安全评测的真实生成模型。

## 必须由公司或外部环境完成

1. 填写备案主体、服务角色、域名/App、服务对象、上线地区和联系人；
2. 完成真实训练数据授权、敏感个人信息单独同意、个人信息保护影响评估和删除机制；
3. 由医学或健康专业人员复核训练集和红队集，在受控GPU环境完成生成模型微调；
4. 扩大跨设备、跨人群、静息及运动数据，达到冻结门槛后才能生成激活清单；
5. 接入实名认证、鉴权、TLS、密钥管理、投诉申诉、撤回同意和人工干预系统；
6. 由公司合规人员确认深度合成备案字段、标识实现和医疗器械软件边界；
7. 取得备案编号后再公示，不得使用当前研究指标进行医疗效果宣传。

这些事项需要公司的法律身份、真实业务系统、数据权利或GPU资源，不能由本地代码替代。
